# game16 作り直し仕様（REBUILD_SPEC）

対象: game16「なわとびジャンプマスター」を、ゲームとして成立する形に全面リニューアルする。
書き換えるファイル: `index.html` / `assets/css/styles.css` / `js/app.js` の3点のみ。
変更しないもの: GAME_ESSENCE.md / REQUIREMENTS.md / REDESIGN_NOTES.md / harness/ 配下 / 他ゲーム / ルートの index.html・metadata.json。

## 背景（現行版の致命的な問題）
- 判定は「1拍に1回・拍の頭」だが、縄の見た目は1拍で足元を2回通り、リズムバーの説明文（中央が目安）とも食い違い、指示どおりに押すとミスになる。
- 開始直後の最初の判定が GO と同時で反応不可能。
→ タイミングの基準を1つに統一することが最優先。

## コア仕様（タイミングモデル：唯一の基準）
- 拍周期 T = 60000 / BPM (ms)。BPMは70〜150、初期値96。
- スタート後、まず4拍のカウントイン（画面表示 3・2・1・GO を拍に同期、各拍で tick 音）。GO の次の拍から判定対象の「縄の通過」が始まる。
- 縄は1拍に1回だけ足元を通過し、通過の瞬間 = 拍時刻 k*T と完全一致させる（見た目と判定を同じ phase から導出すること）。
- 判定: 押下時刻と最寄りの拍時刻の差 delta で判定。
  - |delta| <= 判定幅 → 成功。比率で PERFECT (<=0.35) / GREAT (<=0.72) / GOOD (<=1.0)。
  - 判定幅は難易度別: EASY 130ms / NORMAL 98ms / HARD 72ms。スコア倍率 1 / 1.2 / 1.5（現行踏襲）。
  - 判定幅の外で押した場合は、その拍について EARLY / LATE ミスとして消費。
  - 拍時刻 + 判定幅 を過ぎても押されなければ MISS（縄が足に当たる）。
  - 1つの拍は最大1回だけ解決される。
- ミスでライフ -1（初期3）。ライフ0でゲームオーバー。
- スコア: 成功で 100 + combo*10（倍率適用）。コンボは成功で+1、ミスで0。
- ベストは localStorage キー `jump16_best_score_v4` を踏襲して保存。

## 画面・演出（Canvas描画、横向き視点）
- キャラクター: 頭・体・腕・脚のある人物を図形で描く。縄の持ち手を持つ。待機中は小さく上下動。成功ジャンプ時は足が縄を越えるよう跳ね、着地で軽くつぶれる（スカッシュ＆ストレッチ）。
- 縄: キャラを中心に回るループとして描く。拍の瞬間に足元を通過し、半拍ずれた時点では頭上にあることが一目で分かること。通過前後は残像（ゴースト）で動きを強調。
- ガイド: 足元に「収縮するリング」を表示し、リングが足元の点に重なる瞬間 = 通過の瞬間にすること（リズムゲーム式）。これが唯一のタイミングガイド。旧リズムバーとその説明文は廃止。
- 判定演出: 判定文字（PERFECT=金 / GREAT=緑 / GOOD=青 / MISS=赤）がキャラ上部に浮かんで消える。PERFECTで金色パーティクル+リング拡散。コンボ10/20/30到達でバナー表示。
- ミス演出: 縄が足元で止まって絡まり、キャラがよろける（傾き+汗マーク等）。画面端に赤いビネットを一瞬。ライフのハートが割れる表現はHUD側で。
- 背景: 空のグラデーション+簡単な地面とライン。軽量に。

## UI構成
- ヘッダー: タイトル / BPMスライダー（値表示つき）/ 難易度セグメント（EASY/NORMAL/HARD）。
- HUDチップ: Score / Combo / Best / Life（❤）/ Rate（成功率）。Streakチップは廃止（Comboに統合）。
- ステージ: Canvas + オーバーレイ（開始前 / カウントイン / ポーズ / ゲームオーバー）。
  - 開始前: 「タップ / Space で開始」+ 一行説明「縄が足元に来る瞬間にタップ」。
  - ゲームオーバー: スコア、ベスト、判定内訳（PERFECT/GREAT/GOOD/MISS数）、「もう一回」ボタンで即リスタート（カウントインから）。
- フッター: 大きな JUMP ボタン、一時停止、リセット、Sound ON/OFF トグル。
- 廃止: 多段チュートリアル、判定履歴チャート、Haptic切替ボタン（navigator.vibrate はミス時・成功時に短く使うのは可）。

## 操作
- 画面タップ（ボタン・スライダー上は除く）/ JUMPボタン / Space / Enter でジャンプ入力。
- ボタンやスライダーの操作でジャンプが発火しないこと。Space/Enter は preventDefault。

## 技術要件
- バニラJS（ES Modules）、外部依存なし。requestAnimationFrame 1ループ。
- 経過時間は performance.now() ベース。dtクランプでタブ復帰時に暴走しない。一時停止は経過時間を保持して再開できる。
- devicePixelRatio 対応リサイズ。幅約390pxのスマホ縦画面で横スクロールが出ず、主要UIが破綻しない。
- 音: WebAudio の簡易ビープ（拍tick / 成功ティア別トーン / ミス低音）。AudioContext は最初のユーザー操作で初期化。
- 60fpsを阻害しない軽量描画（パーティクルは上限を設ける）。

## Timing revision v2（2026-10-28、ユーザーの実プレイフィードバックを受けて最優先で適用）

実プレイで「どのタイミングで押すのか分からない。縄が足元に来る前に跳ぶ感覚と合わない。2回目・3回目が続かない」という指摘があった。原因は v1 のモデルが「縄が足元に触れる瞬間に押す」ことを要求し、キャラクターのジャンプが押下後に始まって頂点が通過の約260ms後になるため、成功しても見た目が失敗に見えることにある。以下に差し替える。

### 新タイミングモデル
- 各拍 k の「通過時刻」は従来どおり pass_k = k·T（T = 60000/BPM ms）。縄の描画位相も従来どおり pass の瞬間に足元を通る。
- 判定の中心を「押下目標時刻」target_k = pass_k − LEAD に移す。LEAD = 170ms。
- プレイヤーは「縄が下りてきて足元に近づいたら押す」のが正解になる。押下目標の瞬間に縄のビーズは足元まで残り約170msの位置（下り途中）にいる。
- 判定窓は target_k 基準で従来どおり（難易度ごとの hitWindow、PERFECT/GREAT/GOOD の比率も不変）。EARLY/LATE は target_k 基準の符号で出す。
- 拍の割り当て: beatIndex = round((elapsed + LEAD) / T)。beatIndex < 1 の押下は無視（GO直後のガードはこの式に内包されるので旧 beatFloat<0.5 ガードは削除）。
- 割り当てた拍が解決済み（beatIndex <= lastResolvedBeat）の場合: 次の未解決拍の target までの距離が T×0.75 以内なら、その拍として再割り当てして判定する。それ以外は無視する（無反応で握りつぶさないための救済）。
- 自動ミス: 未解決の拍 k について elapsed > pass_k + 30ms で MISS を確定する（縄が足をすり抜けた見た目と一致させる）。押下によるミス確定（窓外）は従来どおり即時。

### ジャンプアニメーション（物理演算からパラメトリックへ差し替え）
- 成功時のジャンプは時刻ベースの放物線にする: airTime = min(0.34s, 0.8 × T秒)、高さ 70px、jumpY = −70 × sin(π × t / airTime)（t は押下からの経過秒）。
- 頂点は押下の約170ms後 = target 通りに押せば通過の瞬間と一致する。着地は次の拍までに十分余る。
- スカッシュ＆ストレッチや影のスケールは jumpY とその変化方向から従来どおり導出してよい。gravity / jumpPower による物理更新は廃止。

### ガイドとキュー
- 収縮リングは「次の押下目標時刻」に向けて閉じるよう変更する（通過時刻ではない）。rem = (target_next − elapsed) / T ∈ (0, 1] を残り割合とし、rem → 0 でリングが足元の点と重なる。目標の瞬間には足元に短い金のフラッシュを出す。
- 拍ティック音: running 中、各 target_k の瞬間に小さいティック音を鳴らす（Sound ON のときのみ）。カウントインの拍でも鳴らす。update ループで target 通過を検出して発音する。
- GOOD 判定の浮動文字には EARLY / LATE の小ラベルを併記する（例「GOOD (EARLY)」）。PERFECT / GREAT は従来どおり。
- 開始前オーバーレイとゲームオーバー画面の説明文を「リングが閉じる瞬間にタップ（縄が足元に来る直前が目安）」に差し替える。

### 変更範囲
- 原則 js/app.js のみ。説明文が index.html 側にある場合は index.html の該当テキストのみ変更可。styles.css は変更しない。
- 上記以外の仕様（スコア、ライフ、BPM、難易度、保存キー、演出の種類）は v1 のまま。

## Rendering revision v2.1（2026-10-28、ユーザーの実プレイフィードバックを受けて適用）

実プレイで「ジャンプが成功したときに、縄が人の周りを周りきっていない時がある。縄跳びとして不自然」との指摘があった。現状の縄は「両手から先端のビーズへ収束する2本のストランド」で描かれており、ループとして人の周りを一周して見えないのが原因。タイミングモデル（v2）は一切変えず、縄の描画だけを以下に差し替える。

### 縄を「閉じたループ」として描く
- 縄は、既存の楕円軌道（中心 pivot、半径 rx / ry）上を位相 phase とともに移動する4つのアンカー点で定義する閉じたループにする。
  - P0 = getRopePoint(phase)（phase=0 で足元の通過点）
  - P1 = getRopePoint(phase + 0.25)（背中側を上がる点）
  - P2 = getRopePoint(phase + 0.5)（頭上の点）
  - P3 = getRopePoint(phase + 0.75)（前面を下りる点）
- ループの描画順は P0 → P1 → P2 → P3 → P0。中点を使った滑らかな閉曲線（quadratic の midpoint 法、または Catmull-Rom 相当）で描くこと。角が立たないこと。
- これにより縄は常に人の周りを囲む1本の輪として見え、1拍に1回、輪の下部が足元をくぐる。位相が進むにつれて輪全体が回って見えること。

### 奥行き（前後の描き分け）
- 背面アーク（P0 → P1 → P2）はキャラクターより後ろに描く。
- 前面アーク（P2 → P3 → P0）はキャラクターより前に描く。
- 持ち手との接続: 奥の手（handFar）から P1 付近へ、手前の手（handNear）から P3 付近へ、それぞれ短い直線（または緩い曲線）でつなぐ。手首の円運動オフセットは従来どおりアンカーにも手にも効かせて一体感を保つこと。

### ビーズと残像
- 光るビーズは P0（足元を通過する先行点）に置き、タイミングの目印として従来どおり残す。
- 残像（ゴースト）はストランドではなく、P0 の過去位置のビーズのみに簡素化する（従来のステップ間隔・本数の考え方は流用可）。

### 維持するもの
- 軌道ガイドの点線楕円と頭上マーカーは残してよい（薄く）。
- ミス時の絡まった縄（drawTangledRope）とよろけ演出は現状のまま。ミス中はループを描かない（従来どおり）。
- 待機中（ready）は phase を固定して輪が静止して見える現状の扱いを踏襲する。
- タイミング・判定・リング・音など v2 の仕様は変更しない。変更は js/app.js の描画まわりのみ。
